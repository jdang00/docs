## What Question Studio does

**Question Studio** turns a processed Content Library document into draft multiple-choice questions for a specific module through a structured, source-bounded authoring workflow.

You choose:

- the source document
- the pages or mapped topics the agent may read
- the destination semester, class, and module
- the number and mix of questions
- optional focus notes

Question Studio plans the run, drafts questions in parallel, checks the results, and gives you a review workspace. Nothing is published automatically.

## Start a question run

Open **Admin → Question Studio**, then complete the setup sentence.

<Steps>
  <Step title="Choose Pages or Topics">
    **Pages** is the default for a new user. Choose exact pages when you want tight control or when topic mapping is unavailable. Choose **Topics** to work from the reusable topic map prepared during document processing.
  </Step>
  <Step title="Attach a document">
    Select a document from your cohort's Content Library. A document must finish enough of the processing pipeline for Question Studio to read its extracted text. Topic mode also requires a completed topic map.
  </Step>
  <Step title="Set the source scope">
    In **Pages**, select thumbnails, use **Select all**, or enter ranges such as `1–12, 24, 38–45`. In **Topics**, search the mapped topics and keep only the concepts you want covered.
  </Step>
  <Step title="Choose the destination">
    Select the semester, class, and module where accepted drafts should be saved. Question Studio requires the destination before generation begins.
  </Step>
  <Step title="Set the question mix">
    Request between `1` and `30` questions, then divide the total among **Learn**, **Clinical**, and **Critical thinking**.
  </Step>
  <Step title="Add focus notes and generate">
    Use the optional notes field for priorities such as key definitions, common misconceptions, or areas to avoid. Click **Generate questions** when the source, scope, destination, and mix are ready.
  </Step>
</Steps>

## Question types

| Type | What it asks the learner to do |
| --- | --- |
| **Learn** | Reinforce a source-supported fact, relationship, definition, or distinction. |
| **Clinical** | Apply the source to a focused patient scenario, finding, or clinical decision. |
| **Critical thinking** | Combine source-supported relationships, interpret evidence, or weigh meaningful alternatives. |

Question Studio creates clinical questions only when the selected source supports clinical application. Insufficient evidence can produce fewer usable questions than requested.

## Pages and topics

Use **Pages** when:

- only a specific lecture section belongs in the run
- the topic map is unavailable or needs attention
- you want to inspect the exact extracted text used for generation

Use **Topics** when:

- the document has completed the **Mapped** stage
- you want reusable concept-level selection across a large document
- you want to search topic titles, summaries, or key terms

Question Studio remembers your Pages/Topics preference for your account in the same browser. Learn more in [Source context](/admin/source-context).

## Review the run

Candidates appear as workers finish, so you can start reading before the full run completes. The review workspace lets you:

- browse candidates from the question list
- inspect the stem, options, correct answer, rationale, and source pages
- open source citations and quoted evidence when available
- see warnings for ambiguity, duplication risk, or limited checking
- edit a candidate after the run is ready
- select all, select none, or keep only individual candidates

Question Studio can reject or cut a candidate that is unsupported, ambiguous, duplicative, or structurally weak. The requested count is a target, and the final review set can be smaller.

For the complete review flow, see [Reviewing a Question Studio run](/admin/question-studio-reviewing-runs).

## Save drafts, then publish separately

Click **Save drafts to _module_** to insert the selected candidates. Saved candidates:

- enter the destination module with `draft` status
- stop being selectable in the current run
- remain private until someone publishes them from the module
- retain their generation and source provenance

Use **Open module** after saving to review the inserted drafts in context. Publishing is a separate editorial decision.

<Warning>
Starting a new run discards all unsaved candidates from the current run. Question Studio asks for confirmation when unsaved drafts remain.
</Warning>

## Limits and common blockers

- A run can request up to `30` questions.
- A module can contain up to `150` questions.
- Generation is subject to per-user and service-wide limits.
- A document must have readable extracted text.
- Topic mode requires mapped topics; switch to **Pages** when mapping is unavailable.
- If the source changes during a run, start a new run so citations and page selection remain consistent.

## Recommended workflow

1. Confirm the document is **Ready** in Content Library.
2. Start with a focused page range or a small set of topics.
3. Choose only question types the source can support.
4. Add concise focus notes.
5. Review source support, the correct answer, distractors, and rationale.
6. Edit weak-but-fixable candidates.
7. Save only the drafts you would be willing to publish after a final module review.
